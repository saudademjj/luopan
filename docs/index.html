luopan 罗盘

一个旅游行程规划 skill。排程前先问清预算和范围,事实数据都带来源,交付前自己检查一遍。16 条规则,9 轮真人裁判迭代,在真实城市里一轮一轮试出来的。

两步安装 GitHub 仓库
FEATURES

先立规矩,再排行程

行程排不好,问题多半出在规则没守住。罗盘的每条规则都来自真实行程的翻车现场,一条条写回来的。

01Budget Gate

必问预算

预算没确认前,只输出问题清单,不出行程草稿。口径没定,后面每一步都是空的。

02Scope Red Line

范围红线

行程只覆盖你指定的地方,不擅自加城市。环线跨出范围时说明原因,另给一版严格替代,由你定。

03Source

来源分级

票价、开放时间这类数字优先官方渠道;自媒体和野榜只当线索,标"需官方确认"。每条数据带来源和查询日期。

04Workload

体量定负荷

浏览时间之外,再留出排队、交通、吃饭、拍照的余量;顶流园区独占一天;自驾车程也算进当天负荷。

05Self-check

输出前自检

交付前重读规则,逐条填自检表(带证据)。行程越长规则越容易走样,这一步兜底。

06Deliverables

输出包含

逐日行程表、预算估算(经济/舒适两档)、交通和住宿建议、景点与美食清单(含避雷)、二次确认清单、数据来源索引。

ANTI-DRIFT 01

输出前强制重读

行程写长了,约束会随上下文增长而"磨损"。正式动笔前,把 R1 到 R13 和红线重读一遍,有问题在草稿里改掉,别带到成品。

ANTI-DRIFT 02

规则自检表

输出末尾逐条填写判定(✓ / ✗ / —)和证据,不能留空。每条规则都显式过一遍,走样一眼就能看出来。

FIELD INCIDENT · 伊犁 v2

自检表当场拦下一次违规

规划里"河谷草原 + 巴音布鲁克同日"被自检表拦下(违反 R3 体量 / R4 顶流独占),改成上午休整、午后单去巴音,规则在交付前修正完。

INSTALL

两条命令,装完就能用

支持插件系统的客户端,终端里跑两条命令:先注册,再安装。

terminal · zsh
$ plugin marketplace add saudademjj/luopan
  ✔ 已注册插件源 saudademjj/luopan
$ plugin install travel-planner
  ✔ 已安装 skill travel-planner
本地调试用本地路径:plugin marketplace add /path/to/luopan。也可以把 skills/travel-planner 手动复制到你的 skills 目录。
USAGE

用法很简单,直接说需求

直接描述需求,skill 自动触发;也可以显式调用。第一步先收集需求,预算必问。

YOU · 苏州 「帮我规划去苏州 5 天,带爸妈」
YOU · 北京 「北京 7 天 6 晚,情侣,预算中等」
YOU · 伊犁 「伊犁自驾 9 天,5 人,从乌鲁木齐出发」
第一步先收集需求(预算必问),确认后才联网调研、排行程。
